# Security Policy

PassForge generates passwords, so security reports are taken seriously.

## Reporting a vulnerability

Please **do not** open a public issue for a vulnerability that could put users at risk.
Instead, use GitHub's private vulnerability reporting:

<https://github.com/BrathonBai/passforge/security/advisories/new>

Include the affected version, a description, reproduction steps, and any suggested fix.
You can expect an initial response as soon as reasonably possible.

## Scope

In scope:

- `generator.js` randomness, bias, character-set or guarantee logic
- password handling in `popup.js`, `background.js` and `fill-page.js`
- permission, injection, clipboard or storage behavior
- the packaged ZIP and update path

Out of scope:

- websites rejecting specific characters or length limits (a product compatibility issue)
- passwords generated by older versions that a user chose to keep using
- vulnerabilities in Chrome itself or in third-party password managers

## Design commitments

- No `Math.random()` fallback.
- No network requests, analytics, remote code or password storage.
- No broad host permissions or persistent content scripts.
- Generated passwords are never sent to the developer.
